# Manual Client Ops Runbook

This runbook is the day-to-day operating guide for handling Szymik Digital enquiries, quotes, projects, previews, feedback, launch, and handover.

It is deliberately manual. It explains how Ric and Hannah should work with the inbox, tracker, folders, templates, quotes, approvals, and client communication without assuming automation, a CRM, payment software integration, or a future client portal.

## Purpose

Use this runbook when a real enquiry or active project needs moving forward.

It explains:

- How enquiries are reviewed and logged.
- How quotes, approvals, and deposits are handled.
- How project folders, assets, content, previews, feedback, and changes are managed.
- How launch approval, launch checks, handover, and follow-up should work.

The aim is simple: every client should have one clear next action, every active item should have an owner, and Ric should not be pulled into unclear work before Hannah has tidied the admin and client communication around it.

## Roles

### Hannah

Hannah owns:

- Client-facing communication.
- Inbox review and enquiry triage.
- Tracker updates.
- Choosing and adapting templates from the comms pack.
- Requesting missing information, assets, content, feedback, approvals, and payments where appropriate.
- Cleaning client feedback into task lists.
- Keeping follow-ups moving.
- Coordinating handover and post-launch check-ins.

### Ric

Ric owns:

- Technical review.
- Fit decisions.
- Scope, pricing, timeline, and build approach confirmation.
- Technical answers.
- Build work.
- Review of unclear or out-of-scope feedback.
- Launch.
- Final technical checks.

### Client

The client owns:

- Providing clear information.
- Supplying assets, copy, access, and business details.
- Reviewing quotes and previews.
- Sending feedback in a clear list where possible.
- Giving written approval.
- Paying deposits, balances, and agreed additional work where relevant.

## Daily / Weekly Operating Rhythm

### Daily

- Hannah checks the enquiry inbox.
- Hannah adds new enquiries to the tracker.
- Hannah updates statuses, owners, next actions, due dates, and notes.
- Hannah sends enquiry received, more information, discovery, quote, asset, feedback, approval, or follow-up messages from the comms pack where needed.
- Ric reviews any rows marked `Awaiting Ric Review`.
- Ric gives Hannah the decision or answer needed for the next client message.

### Weekly

- Review all active tracker rows.
- Check anything with `Waiting on Client`, `Needs More Info`, `Quote Sent`, `Preview Sent`, `Awaiting Approval`, or `Final Payment Due`.
- Send polite follow-ups where useful.
- Park projects that have had no response after the agreed follow-up window.
- Check active project folders for missing assets, scattered feedback, or handover notes that need tidying.

## New Enquiry Workflow

1. Enquiry arrives through the website email draft or direct email.
2. Hannah checks whether enough information is present.
3. Hannah adds the enquiry to the tracker.
4. Hannah sets the status, owner, next action, and due date.
5. If the enquiry is clear enough, Hannah sends the enquiry received message.
6. If details are missing, Hannah sends the more information or discovery questions template.
7. If Ric needs to decide fit, scope, technical route, or quote readiness, Hannah marks the row `Awaiting Ric Review`.
8. Ric reviews the enquiry and decides the next action.
9. Hannah sends the next client message: more questions, call offer, quote timing, quote, hold/park, or polite decline.

## Quote Workflow

1. Ric confirms the scope, price, timeline assumptions, exclusions, payment terms, and build approach.
2. Hannah prepares or sends the quote message using the quote pack and comms pack.
3. Hannah adds the quote link, quote value, quote date, follow-up date, and status to the tracker.
4. Set status to `Quote Sent`.
5. Set owner to `Client` or `Waiting on Client`.
6. Follow up if the client has not replied by the follow-up date.
7. Client approves the quote in writing.
8. Hannah records the approval in the tracker and project folder where useful.
9. Hannah sends the deposit/payment request where relevant.
10. Hannah records deposit/payment status.
11. Once quote approval and payment conditions are met, the project can move into `Active Projects`.

## Project Start Workflow

1. Hannah creates the project folder using `docs/project-folder-template.md`.
2. Hannah adds the folder link to the tracker.
3. Hannah requests assets, content, access, and business details using the comms pack.
4. Hannah records what has been received and what is missing.
5. Hannah confirms project start only once Ric confirms the start point.
6. Ric begins build work only when the agreed approval and payment conditions are met.
7. Hannah keeps the tracker current while Ric works.
8. Missing assets stay visible as a next action until resolved.

## Preview And Feedback Workflow

1. Ric prepares the preview.
2. Hannah reviews internally first from a client/user perspective.
3. Hannah sends Ric one clean internal review list if anything obvious needs attention before the client sees it.
4. When Ric confirms the preview is ready, Hannah sends the preview link with clear review instructions.
5. Client sends feedback.
6. Hannah gathers feedback into one clean task list.
7. Hannah separates in-scope amendments, clarification questions, and possible scope changes.
8. Ric reviews anything unclear or potentially out of scope.
9. Ric makes agreed changes.
10. Hannah verifies completed changes against the clean task list.
11. Client approves or requests the next agreed revision round.

## Scope Change Workflow

Small included amendments can continue within the agreed revision rounds.

Pause and check with Ric before committing to:

- New pages.
- New features.
- Major redesigns.
- Large content rewrites.
- New integrations.
- New automation or CRM-style requirements.
- Work that was specifically excluded from the quote.

Hannah should not promise extra work, new timings, or free additions before Ric confirms whether the request is included, should be quoted separately, should move to a later phase, or should be declined.

## Launch Workflow

1. Final preview is approved in writing.
2. Hannah checks final payment status or confirms any Ric-approved payment agreement.
3. Hannah confirms domain, hosting, DNS, or launch access is ready where relevant.
4. Ric completes the launch checklist and final technical checks.
5. Ric launches the website.
6. Ric checks the live site.
7. Hannah or Ric checks contact form or mailto routes, phone/email links, mobile layout, and basic SEO items where in scope.
8. Hannah updates the tracker with live link, launch date, and launch status.
9. Hannah sends launch confirmation to the client.

## Handover Workflow

1. Hannah sends the live website link.
2. Hannah sends handover notes, access guidance, support notes, or editing guidance where relevant.
3. Hannah confirms the support/check-in period or next support route.
4. Hannah requests a testimonial or review when appropriate.
5. Hannah moves the tracker row to `Completed Projects` when launch and handover are complete.
6. Hannah adds a future follow-up if useful.
7. Folder links, handover notes, approval records, and final project status should be easy to find later.

## Tracker Status Rules

Use these statuses consistently in the tracker.

| Status | Meaning |
| --- | --- |
| New Enquiry | A new enquiry has arrived and has not yet been triaged. |
| Needs Hannah Review | Hannah needs to check details, add notes, or decide the next admin step. |
| Awaiting Ric Review | Ric needs to review fit, scope, price, technical route, or answer a question. |
| Needs More Info | The client needs to send more detail before the next decision can be made. |
| Discovery Call Needed | A call should be offered or booked before quote/scope is confirmed. |
| Quote To Prepare | Ric has decided a quote is needed, but it has not been sent yet. |
| Quote Sent | The quote has been sent and the client is reviewing it. |
| Approved / Awaiting Deposit | The client has approved in writing, but deposit/payment conditions are not complete. |
| In Progress | Approved work has started and Ric is actively building or delivering. |
| Internal Review | Work is ready for Hannah/Ric internal review before the client sees it. |
| Preview Sent | The client has the preview and needs to review or send feedback. |
| Changes Requested | Client feedback has been received and needs cleanup or review. |
| Changes In Progress | Ric is working through agreed feedback changes. |
| Awaiting Approval | The client needs to approve the latest preview or final changes. |
| Approved for Launch | Written launch approval has been received. |
| Final Payment Due | Final payment is needed before launch or handover unless Ric has agreed otherwise. |
| Live | The website or agreed deliverable is live. |
| Completed | Launch, handover, and immediate wrap-up are complete. |
| Parked / No Response | The client has not responded and the project/enquiry is paused. |
| Not a Fit | Ric has decided the enquiry is not suitable for Szymik Digital to take on. |

## Who Has The Ball?

Every active row should have one clear owner and one clear next action.

Use the Owner field to show who needs to act next:

- Hannah
- Ric
- Client
- Waiting on Client
- External provider

Examples:

- Owner: Hannah. Next action: send discovery questions.
- Owner: Ric. Next action: confirm quote scope and price.
- Owner: Client. Next action: send logo files and service descriptions.
- Owner: Waiting on Client. Next action: approve preview or request changes by [Due Date].
- Owner: External provider. Next action: hosting provider to confirm DNS change.

If nobody clearly has the ball, the project is stuck.

## Common Mistakes To Avoid

- Starting work without clear written approval.
- Starting paid work before deposit/payment terms are met.
- Letting feedback stay messy instead of turning it into tasks.
- Letting projects sit without a next action.
- Promising timelines before Ric confirms.
- Sending previews before internal review.
- Launching without written approval.
- Launching before final payment unless Ric has agreed otherwise.
- Losing project assets outside the folder structure.
- Treating the tracker as optional once the project gets busy.
- Adding new pages, features, or rewrites without checking scope.

## Quick Checklists

### New Enquiry Checklist

- Enquiry added to tracker.
- Status set.
- Owner set.
- Next action added.
- Due date or follow-up date added.
- Hannah notes added.
- Missing information requested if needed.
- Marked `Awaiting Ric Review` if Ric needs to decide the next step.

### Quote Sent Checklist

- Scope confirmed by Ric.
- Price confirmed by Ric.
- Timeline assumptions confirmed by Ric.
- Quote link added to tracker.
- Quote value added to tracker.
- Status set to `Quote Sent`.
- Follow-up date added.
- Approval wording included.

### Project Start Checklist

- Written quote approval received.
- Deposit/payment terms met or Ric-approved exception recorded.
- Project folder created.
- Folder link added to tracker.
- Assets/content requested.
- Missing items tracked.
- Project status moved to `In Progress` only when start conditions are met.

### Preview Sent Checklist

- Ric confirms preview is ready.
- Hannah internal review completed where appropriate.
- Preview link checked.
- Feedback instructions included.
- Feedback deadline included.
- Revision round noted.
- Tracker status set to `Preview Sent`.

### Launch Checklist

- Final preview approved in writing.
- Final payment received or Ric-approved payment agreement recorded.
- Domain/hosting access ready.
- Contact form or mailto route tested.
- Phone/email links checked.
- Mobile checked.
- Basic SEO checks complete where in scope.
- Backup/export saved where relevant.
- Handover notes prepared.

### Handover Checklist

- Live link sent.
- Handover notes sent.
- Access or editing guidance sent where relevant.
- Support/check-in route explained.
- Testimonial/review request sent when appropriate.
- Tracker moved to `Completed`.
- Follow-up added if useful.
- Project folder tidied.
