# Client Delivery Flow

This is the internal operating flow for moving a Szymik Digital client from first enquiry to launch, handover, and follow-up.

The aim is simple: keep enquiries organised, keep Ric focused on delivery decisions and build work, and give Hannah a clear structure for triage, admin, feedback, review, and client communication.

## Core Roles

### Ric's Responsibilities

- Decide whether an enquiry is a good fit
- Lead discovery, technical judgement, scope, and quoting decisions
- Confirm what is included and excluded before work starts
- Build the website, refresh, local growth work, or agreed system/tool discovery
- Review Hannah's task lists before implementing changes where needed
- Complete launch checks that require technical access or build knowledge
- Confirm the final handover notes are accurate

### Hannah's Responsibilities

- Monitor incoming enquiries
- Triage enquiries and add them to the client tracker
- Gather missing information before Ric reviews where appropriate
- Keep statuses, notes, due dates, links, and payment state updated
- Help prepare clean project admin: folders, assets, feedback notes, and follow-ups
- Convert client feedback into a clear task list
- Verify completed changes against the agreed feedback list
- Support handover, testimonial requests, and follow-up reminders

### Client Responsibilities

- Provide accurate business information
- Share required assets, copy, access, logins, and approvals on time
- Review quotes, previews, and feedback requests within agreed windows
- Keep feedback consolidated and tied to the agreed scope
- Pay deposit, balance, and any agreed additional work on time
- Confirm final approval before launch

## Full Enquiry-To-Launch Process

### 1. Client Submits Enquiry

The client submits an enquiry through the website contact route or by direct email.

The enquiry should ideally include:

- Client name
- Business name
- Email and phone if available
- Project type or problem
- Existing website link if relevant
- Desired timeline
- Any urgent context

### 2. Enquiry Lands In Inbox

Hannah checks the inbox and confirms whether the enquiry has enough information to be added to the tracker.

If key information is missing, Hannah can send the "More information needed" or "Discovery questions" template before Ric reviews.

### 3. Hannah Reviews And Triages

Hannah checks:

- Is this a real business enquiry?
- Does it match Szymik Digital's current offer pathways?
- Is the request urgent?
- Is there enough information for Ric to review?
- Are there any obvious red flags, such as vague unpaid work, unrealistic promises, or requests outside the service ladder?

### 4. Hannah Adds Enquiry To Tracker

Hannah adds the enquiry to the `Enquiries` tab of the client tracker.

Minimum tracker fields at this point:

- Date received
- Client name
- Business name
- Email
- Enquiry type
- Source
- Status
- Hannah notes
- Next action
- Due date

### 5. Ric Reviews And Decides Next Action

Ric reviews the enquiry and Hannah's notes.

Possible next actions:

- Send discovery questions
- Book a call
- Prepare quote
- Ask for more information
- Decline politely
- Hold for later follow-up

### 6. Discovery / Quote / Call / Decline Decision

Use the lightest useful next step:

- If the problem is clear and small, Ric may quote directly.
- If the scope is unclear, send discovery questions or book a call.
- If the request is automation/custom tool related, discovery should usually happen before any build quote.
- If the work is not a fit, decline clearly and politely.

### 7. Quote Sent

The quote should include:

- Project type
- Scope summary
- Included deliverables
- Exclusions
- Client responsibilities
- Revision rounds
- Timeline assumptions
- Deposit and balance terms
- Quote expiry date

Hannah records the quote value, payment status, and quote link in the tracker.

### 8. Client Approval

Work does not start until the client has approved the quote in writing.

Approval can be by email, signed document, or another clear written confirmation.

### 9. Deposit / Project Start

Deposit is due before project work begins unless Ric has agreed a different arrangement in writing.

After deposit is received:

- Hannah updates payment status
- Hannah moves the client to `Active Projects`
- Hannah creates or checks the client folder
- Ric confirms the start point and first project milestone

### 10. Asset Collection

Hannah requests required assets and tracks what has been received.

Common assets:

- Logo files
- Brand colours or existing brand guide if available
- Photos
- Service descriptions
- Existing website/CMS access where needed
- Domain and hosting access where needed
- Google Business Profile details where relevant
- Testimonials, reviews, accreditations, and trust content

### 11. Ric Build Phase

Ric carries out the agreed build or delivery work.

Hannah keeps the tracker current and can help chase missing client inputs without interrupting build focus.

### 12. Hannah Internal Review

Before the client preview is sent, Hannah reviews the work from a client/user perspective.

Check for:

- Obvious typos
- Broken or unclear links
- Missing agreed content
- Confusing wording
- Layout issues that are easy to spot
- Whether the page matches the agreed scope

Hannah sends Ric one clean internal review list.

### 13. Client Preview Sent

Ric or Hannah sends the preview link with clear review instructions.

The message should tell the client:

- What to review
- How to send feedback
- Feedback deadline
- How many revision rounds are included
- That feedback should be consolidated where possible

### 14. Client Feedback Received

Hannah collects the feedback and checks whether it is clear enough to act on.

If feedback is scattered across email, messages, and documents, Hannah consolidates it before Ric starts changes.

### 15. Hannah Converts Feedback Into A Clean Task List

The task list should separate:

- In-scope amendments
- Questions needing clarification
- Out-of-scope requests
- Nice-to-have items for later

Each task should be written clearly enough for Ric to complete without rereading the full email chain.

### 16. Ric Makes Changes

Ric completes agreed changes from the clean task list.

If a request is out of scope, Ric decides whether to quote it separately, defer it, or decline it.

### 17. Hannah Verifies Changes

Hannah checks the completed changes against the task list.

If something is missing or unclear, Hannah flags it back to Ric before the client is asked to review again.

### 18. Client Final Approval

Client final approval is required before launch.

Final approval should be written and should confirm that the client is happy for the site to go live.

### 19. Final Payment

Final payment is due before launch unless Ric has agreed otherwise in writing.

Hannah updates payment status in the tracker.

### 20. Site Launch

Ric handles launch or supervises launch depending on the project setup.

Hannah keeps the tracker updated with live link, launch date, and handover status.

### 21. Launch Checks

Run the launch checklist below.

Any serious issue should be fixed before the project is marked as launched.

### 22. Handover

Handover should give the client what they need without overloading them.

Hannah can send the handover email and record the handover link or notes in the tracker.

### 23. Testimonial / Follow-Up

After launch, Hannah schedules a follow-up.

Typical follow-up points:

- Short launch check-in
- Testimonial request
- Support/maintenance offer
- Reminder of how to request future changes

## Recommended Project Statuses

Use these statuses in the tracker:

- New Enquiry
- Needs Hannah Review
- Awaiting Ric Review
- Needs More Info
- Discovery Call Needed
- Quote To Prepare
- Quote Sent
- Approved / Awaiting Deposit
- In Progress
- Internal Review
- Preview Sent
- Changes Requested
- Changes In Progress
- Awaiting Approval
- Approved for Launch
- Final Payment Due
- Live
- Completed
- Parked / No Response
- Not a Fit

## Approval Rules

- No project starts without written quote approval.
- No project starts without deposit unless Ric has agreed otherwise in writing.
- No launch happens without written final client approval.
- No launch happens before final payment unless Ric has agreed otherwise in writing.
- Out-of-scope work must be confirmed before it is added.
- Client claims, testimonials, case study details, and regulated wording must not be invented.

## Amendment / Revision Round Rules

Default structure:

- One structured review round after the first complete preview
- One smaller follow-up round for agreed refinements

Rules:

- Feedback should be consolidated where possible.
- Amendments should stay within the agreed scope.
- New pages, new features, major direction changes, and repeated rewrites are scope changes.
- Out-of-scope work should be quoted or deferred before Ric starts it.
- Hannah should convert client feedback into a clean task list before Ric makes changes.

## Launch Checklist

Before launch, confirm:

- Final client approval received
- Final payment received or approved exception recorded
- Key pages checked
- Navigation checked
- Contact routes checked
- Forms or mailto links tested where relevant
- Mobile layout checked
- Desktop layout checked
- Important links tested
- Page titles and meta descriptions checked where relevant
- Favicon and brand assets checked
- Domain/DNS/hosting setup confirmed
- Analytics or tracking checked if included in scope
- Privacy/terms links checked if included or already present
- Backup or rollback plan considered where relevant
- Live site checked after launch

## Handover Checklist

Before marking handover complete, confirm:

- Live website link sent
- Admin/CMS access confirmed where relevant
- Hosting/domain ownership or access clarified
- Basic editing guidance sent where relevant
- Handover notes sent
- Support/maintenance options explained
- Any known exclusions or future recommendations noted
- Testimonial/follow-up scheduled
- Client folder and tracker updated
