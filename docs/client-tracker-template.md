# Client Tracker Template

This tracker should be practical enough to recreate in Google Sheets or Notion. Keep it simple first. It is not a full CRM.

## Suggested Tabs

### Enquiries

Use for all new and early-stage enquiries before a project is approved.

### Active Projects

Use once a quote is approved and the deposit/project start point is confirmed.

### Completed Projects

Use once a project is launched, handed over, and no longer in active delivery.

### Follow-Ups

Use for testimonial requests, support check-ins, no-response reminders, and future opportunity reminders.

### Templates / Links

Use for quick links to email templates, folder templates, quote templates, common documents, and useful internal references.

## Recommended Columns

### Date Received

The date the enquiry first arrived.

### Client Name

The main contact person.

### Business Name

The client's business or organisation name.

### Email

The main contact email for project communication.

### Phone

The client's phone number if provided.

### Enquiry Type

The closest offer pathway or request type.

Suggested values:

- Website Refresh
- Starter Website
- Local Growth Website
- Automation / Custom Tool Discovery
- Support / update request
- Other

### Source

Where the enquiry came from.

Examples:

- Website
- Direct email
- Referral
- LinkedIn
- Facebook
- Existing client
- Local contact

### Status

The current state of the enquiry or project.

Use the status list from `manual-client-ops-runbook.md` so the tracker stays consistent.

### Owner

Who has the ball for the next action.

Suggested values:

- Hannah
- Ric
- Client
- Waiting on Client
- External provider

### Hannah Notes

Hannah's triage notes, admin context, missing information, and client communication notes.

### Ric Notes

Ric's fit, scope, build, pricing, or technical notes.

### Next Action

The next thing that needs to happen.

Examples:

- Hannah to send discovery questions
- Ric to review enquiry
- Ric to prepare quote
- Waiting for client assets
- Hannah to chase feedback
- Ric to make changes
- Hannah to verify changes

### Due Date

The date the next action should happen by.

This can be a client deadline, internal reminder, payment due date, feedback due date, or follow-up date.

### Quote Value

The quoted project amount or quoted range if a firm number has not been finalised.

Do not use this column to invent pricing. Record only what has been sent or agreed.

### Payment Status

The current payment state.

Suggested values:

- Not quoted
- Quote sent
- Deposit requested
- Deposit paid
- Balance requested
- Paid in full
- Overdue
- Not applicable

### Preview Link

The preview, staging, draft, or review link sent to the client.

### Live Link

The final live website or delivered tool link.

### Folder Link

The client folder link containing briefs, assets, quote/invoice files, feedback, launch notes, and handover docs.

## Practical Use Notes

- Hannah owns keeping the tracker tidy.
- Ric owns final decisions on fit, scope, quote, build, and launch readiness.
- Every active item should have a status, owner, and next action.
- If a row has no clear next action, it is probably stuck.
- Keep notes brief but useful. The tracker should point to documents, not replace them.
- Avoid adding too many columns early. Add new fields only when they repeatedly solve a real tracking problem.
